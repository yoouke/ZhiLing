# Agent 任务

基础安装完成后，从状态页打开「Agent 任务」，选择「安装并启用」。程序会下载独立 Node 运行环境、校验官方 SHA-256 清单、安装指定版本的引擎与双端消息组件，准备工作目录和本机认证，然后重启消息服务。

这条路径安装和启动实际组件，不要求先填另一套后台地址。首次部署需要联网；中断后可以重新点击安装。当前版本固定组件版本以便复现，升级由维护者验证后调整。

## 日常操作

- **安装并启用 / 修复并启用**：准备组件、重新写入受管桥接配置并启动。修复会把桥接授权恢复为仅管理员，关闭私聊整段转发，采用按用户分开的任务会话。
- **重新联动**：启动已安装的引擎并检查桥接入口及认证，不重复下载。
- **暂停任务服务**：停止任务引擎，日常角色聊天继续运行；下一次普通上线也不会启动它，需重新启用。
- **打开 Agent 控制台**：服务就绪后进入本机控制台，管理模型、任务、工具与审批。

日常消息通道发送 `/dsh 任务内容`；`/dsh stop` 停止当前任务。普通聊天不自动全部转交任务引擎。授权按通信服务的管理员身份判断，不依据角色好感或用户消息自称身份。组件的审批与提问不会由宿主自动代答。

## 数据和服务

| 位置 | 内容 |
| --- | --- |
| `runtime/agent/` | 独立 Node、引擎与包管理组件 |
| `engines/dsh/home/` | 引擎配置、插件、会话和桥接认证缓存 |
| `agent-workspace/` | 当前任务文件 |
| `astrbot/data/plugins/astrbot_plugin_dsh/` | 通信端任务组件 |
| `logs/dsh.log` | 引擎进程日志 |
| `logs/installer.log` | 部署步骤和失败原因 |

引擎和桥接只监听 `127.0.0.1`，端口由程序分配；两个入口互不共用端口。服务健康检查核对插件身份、认证文件时效和 Bearer 认证，不把端口有响应直接当作成功。

模型 Key 从宿主加密存储中解密后只传给引擎启动环境。桥接组件有自己的本机认证缓存，不能把所有第三方文件都视为经过 DPAPI 加密。不要公开 engines 目录、完整数据目录或未脱敏日志。工作目录只是默认任务位置，不是操作系统沙箱。

关闭主窗口时，正在进行的部署和服务启动会继续；结束后宿主按原有空闲机制退出，独立服务进程继续运行。部署期间阻止退出、卸载及服务重配与安装线程互相冲突。

## 验证边界

Windows 回归覆盖宿主逻辑和接口；`Agent deployment smoke` 在 Windows runner 实际下载运行环境、安装引擎和插件、启动进程、检查认证，再停止进程。它不会调用付费模型，也不会登录 QQ。

真实 QQ 收发、模型执行、权限审批往返、扫码及用户桌面上的整包安装仍需另行验收。健康检查通过不等于这些链路已完成。目前仍是一个受管任务引擎；多人格完整运行隔离、其他协议端与多平台登录管理不属于这次实现。
