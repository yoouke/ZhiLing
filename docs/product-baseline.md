# 织灵需求基线

需求依据：用户 PRD V0.2，及 2026-11-04 对实现基础的明确补充。软件名为「织灵」，仓库为 `yoouke/ZhiLing`。旧 `yoouke/PersonaWeave` 已停止维护并归档，不作为新工程基础。

## 必须保留的基础

完整的 Windows 一键安装、独立运行环境、API 检查、自动端口与连接配置、QQ 扫码、主人绑定、人格编辑、表情、语音、唱歌、长期记忆、主动聊天、QQ 签名、状态页、服务启动停止、修改后应用设置、桌面快捷方式、断点恢复和卸载流程。基础来自完整的安装与运行系统，不能退化成对外部后台的连接面板。

## 新增能力与约束

1. 独立 Windows 应用作为唯一推荐入口，自动部署和统一管理后台。普通用户无需编程、服务器或手动拼接环境。
2. DSH 是第一阶段 Agent 引擎，提供实际双端桥接。平台消息进入任务、执行工具、按权限审批、回到原消息通道。未来通过适配层更换引擎，保留人格和可导出记忆。
3. 多人格独立目录：`character.json`、`personality.md`、`memory/`、`knowledge/`、`assets/`、`config/`、`logs/`。隔离身份、记忆、知识、语音、账号、插件和会话。切换后整个运行环境正确联动。
4. 三条创建通道：按提示步骤与 AI 讨论修改；直接粘贴或导入 MD/TXT/角色文件并保留原文；联网搜索已知角色，分别整合官方、二创、社区梗并保留来源，按约定结构输出。创作 API 和运行 API 独立。
5. 角色表达自然、因情境调整，不机械客服化、套结构或复读台词；表演动作可调，不强制。没有官方预设人格，也没有固定性格模板。
6. 记忆与人格分开。支持经历、重要事件、人物关系、长期检索、查看、编辑、删除与备份。跨平台共享同角色经授权的记忆，跨角色和不同身份隐私严格隔离。
7. QQ、Telegram、Discord 等通信平台的登录、连接、状态和恢复由主程序统一管理。Bilibili、X、YouTube 等内容平台通过独立插件扩展浏览、搜索及授权互动。
8. 同一 QQ 通道 NapCat / SnowLuma 二选一。NapCat 优先自动部署；SnowLuma 在许可允许时自动部署，否则检测并连接用户安装端。选择 SnowLuma 时不安装或启动 NapCat。
9. 账号登录 QQ 与主人 QQ 分开，扫码登录后保留有效状态，失效时提示重验。凭据加密；不声称第三方所有缓存天然已加密。
10. 优先使用成熟插件，尤其 DSH 原生插件和 Skill；兼容 MCP 与自定义插件。统一安装、卸载、更新、启停、依赖、版本、配置和按角色授权，提供工具说明，不能只展示插件名。
11. 能力覆盖浏览器、视频、音乐、图片、表情、电脑操作、远程办公、社交与通信；缺少现成插件再自行开发。
12. 主人、熟人、普通与未知用户权限由程序判断。高风险审批、远程认证、私密数据隔离、工具访问限制不能由提示词替代。
13. 一键启动与重新联动：检查引擎、协议端、登录、桥接、插件、消息与 Agent；逐项呈现失败原因。支持托盘、关窗后台、自启动、单实例、服务独立控制和重启/休眠后的恢复。
14. 监控 API 请求、输入/输出 Token、模型、人格、插件与日/周/月统计、费用及预算；明确实际数据与估算。另监控资源、进程、WebSocket、会话和服务状态。
15. 提供 DSH 与通信控制台统一入口，优先保留现成控制台；主程序不依赖 DSH 图形界面才能运行。
16. UI、图标、主题、角色资源、插件、通信平台和引擎适配器支持 DIY。公开角色包默认排除私人记忆、聊天和凭据。插件市场、开发工具与社区分享是后续生态目标。

## 验收方法

按可运行链路验收，不按界面好看、文件数量或测试数量宣布完成。PRD 中 M0–M5 用于内部检查覆盖范围，不代表用户只要一个启动器。完整条件见 `acceptance.md`。
